# Android port

The Rust core and Angular UI are shared with the desktop build. On Android,
the app is intentionally log-import driven: Steam auto-discovery and the
floating overlay are desktop-only. **Settings → Game log → Choose file** opens
the Android picker and imports the selected `UE_game.log` immediately, so the
existing history and bag calculations can be inspected without a running game.

## Current status

- Android-specific Rust guards are in place for Steam discovery and overlay
  window creation.
- The log picker uses the Tauri dialog and filesystem plugins, copies Android
  `content://` selections into app data, and replays the selected log through
  the same parser as the live desktop tailer.
- The narrow layout switches the left rail to a bottom navigation bar and
  hides desktop window controls and overlay settings.
- Rust and Android packaging still need to be run on a machine with the Rust,
  Android SDK, and NDK toolchains installed.

## Build locally

Install the Tauri Android prerequisites, then initialize the platform project
once:

```bash
npx tauri android init
npx tauri android dev
```

For a release APK/AAB:

```bash
npx tauri android build
```

### Build from a phone

The repository includes `.github/workflows/android.yml`. Push the project to
GitHub, open **Actions → Android build → Run workflow**, and download the
`tli-tracker-android` artifact when the run finishes. GitHub Actions installs
the Android SDK/NDK and Rust on its build machine, so neither is required on
the phone.

The Android project generated by `tauri android init` is machine/toolchain
output and is not required for the desktop source checkout. Test the picker
with a copied log file on the device; Steam's Windows path is not meaningful
on Android.
